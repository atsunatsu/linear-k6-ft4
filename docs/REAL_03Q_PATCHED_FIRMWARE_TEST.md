# patched 固件与 patched DigiManager 实机测试说明

## 这份文档给谁看
这份文档是给测试者看的。  
你不需要自己编译，只需要按顺序刷机、替换 EXE、做测试、回报结果。

## 0. 安全要求
只允许：

- 接假负载，或
- 断开天线

不要上空口。  
不要上星。  
不要把这套东西当成量产固件。

## 1. 开始前先准备好这 5 样东西
1. `patched-UVK5DigManager.exe`
2. `patched-UVK5DigManager-diagnostic.exe`
3. `patched-0.3q-bench.packed.bin`
4. 一个原版可工作的 `UVK5DigManager.exe`
5. 一个原版可工作的真实 `0.3q` 固件

其中：

- 正常测试先用 `patched-UVK5DigManager.exe`
- 如果后面需要定位慢节拍或时序问题，再换 `patched-UVK5DigManager-diagnostic.exe`

## 2. 先做第一阶段：固定频点合规 FT4
这一阶段先**不要急着测改频**。  
先证明：`FT4` 在固定频点下能发成一段**第二接收机 / 第二套 WSJT-X 能正常解码**的信号。

### 2.1 刷回原版可工作的真实 0.3q 固件
先确保电台运行的是：

- 原版可工作的真实 `0.3q` 固件

刷完后先看这几件事：

1. 能正常开机
2. 菜单仍然像你熟悉的真实 `0.3q`
3. 数字模式入口还在

如果这 3 件事里有任何一件不对，就先不要继续。

### 2.2 替换 DigiManager
先把原版 `UVK5DigManager.exe` 备份好。  
然后把 DigiManager 换成：

- `patched-UVK5DigManager.exe`

换完后先确认：

1. DigiManager 能正常启动
2. 界面没有明显异常

### 2.3 先做 FT8 回归
先测一次 `FT8`，确认原本可工作的链路没有被补丁破坏。

你只要记录：

- `FT8` 是否还能正常发射：`yes / no`

如果 `FT8` 都坏了，就不要继续测 `FT4`，直接按模板回报。

### 2.4 再测固定频点 FT4
在 `FT8` 正常后，再做一次固定频点 `FT4` 发射测试。

这一阶段最重要的不是瀑布图，而是：

- 第二接收机 / 第二套 `WSJT-X` 能不能正常解码

请记录：

- DigiManager 是否对 `FT4` 有反应：`yes / no`
- 电台是否进入 TX：`yes / no`
- 第二接收机 / 第二套 `WSJT-X` 是否正常解码 `FT4`：`yes / no`

### 2.5 这一阶段通过的标准
只有当下面两件事同时成立，才进入第二阶段：

1. `FT8` 正常
2. 第二接收机 / 第二套 `WSJT-X` 能正常解码 `FT4`

如果第二接收机不能正常解码，就**不要继续判断改频是否成功**。  
此时主问题仍然是 `FT4` 的发送时序不合规。

## 3. 第二阶段：接回 patched 固件验证改频
只有第一阶段已经通过，才做这一部分。

### 3.1 刷入 patched 固件
把电台刷成：

- `patched-0.3q-bench.packed.bin`

刷完后先看：

1. 能正常开机
2. 菜单仍保持真实 `0.3q` 风格
3. 数字模式入口仍存在

### 3.2 再次确认 FT8 和 FT4
仍然使用：

- `patched-UVK5DigManager.exe`

先再做一次：

1. `FT8` 回归
2. 固定频点 `FT4`

目的是确认：

- patched 固件没有把第一阶段已经合格的 `FT4` 再次搞坏

### 3.3 数字模式改频测试
只有当 `FT4` 仍可被第二接收机正常解码，才做改频。

改频测试分两步：

#### A. 空闲态改频
- 进入数字模式
- 不发射
- 修改频率
- 观察频率是否变化

#### B. 发射态改频
- 在数字模式发射期间修改频率
- 观察频率是：
  - `yes`：稳定变化
  - `no`：完全不变
  - `temporary`：短暂变化后又被拉回

同时请继续看第二接收机 / 第二套 `WSJT-X`：

- 改频加入后，`FT4` 是否仍然能被正常解码

## 4. 如果 FT4 还是不能正常发射或不能正常解码，请继续做补充测试
不要直接结束测试。  
请继续做下面两组单端对照。

## 5. 补充测试 A：patched 固件 + 原版 DigiManager
按这个顺序做：

1. 保留当前刷好的 `patched-0.3q-bench.packed.bin`
2. 把 DigiManager 换回原版可工作的 `UVK5DigManager.exe`
3. 再测：
   - `FT8`
   - `FT4`
   - 空闲态改频
   - 发射态改频

这组的目的是看：

- 固件补丁单独存在时，行为是否明显变化

## 6. 补充测试 B：原版固件 + patched DigiManager
按这个顺序做：

1. 把电台刷回原版可工作的真实 `0.3q` 固件
2. 再把 DigiManager 换回 `patched-UVK5DigManager.exe`
3. 再测：
   - `FT8`
   - `FT4`
   - 第二接收机是否能解码 `FT4`

如果这里仍然出现“能发但解不了、看起来比标准 FT4 慢”的现象，就优先说明：

- 当前主问题更像在 `DigiManager` 发送时序

## 7. 如果需要进一步定位慢节拍，再用诊断版 DigiManager
只有在下面这种情况才换成：

- `patched-UVK5DigManager-diagnostic.exe`

适用场景：

- `FT4` 能起发射，但第二接收机始终解不了
- 看起来明显比标准 `FT4` 慢
- 需要维护者继续定位发送节拍

换成诊断版后，请尽量保留：

- 第二接收机 / 第二套 `WSJT-X` 的解码结果
- 必要时再配合 `5957` 抓包或节拍分析

## 8. 最简单的判断顺序
1. `FT8` 先正常
2. 再看固定频点下的 `FT4` 能不能被第二接收机正常解码
3. 只有固定频点 `FT4` 合格后，才继续看改频
4. 如果 `FT4` 不合格，不要先纠结改频
5. 如果 `FT4` 失败，继续做两组单端对照

## 9. 最后按模板回报
请使用这份模板：

- [REAL_03Q_PATCHED_FIRMWARE_RESULT_TEMPLATE.md](/F:/Codex/CEC固件改装FT4/docs/REAL_03Q_PATCHED_FIRMWARE_RESULT_TEMPLATE.md)

至少请回报：

- 开机版本
- 菜单截图
- DigiManager 主界面截图
- `FT8` 是否正常
- `FT4` 是否进入 TX
- 第二接收机 / 第二套 `WSJT-X` 是否解码成功
- 空闲态改频是否生效
- 发射态改频是否生效
- 是否全程假负载或断天线
